# Absolute addresses in the hand-written assembly (source-6psc)

Generated by: Claude Opus 5.5

Since map-order placement replaced address pinning
(docs/design-per-process-data.md, 2026-09-28 amendment), a data cell or
routine reached by its SAU2 image address names different memory from our
object.  This file inventories every absolute address the 66
`<subsystem>/sau2/*.s` files carried at d2da5e6 (inline `(0xE.....).l`,
`#0x......`, `.set`/`.equ` constants, `.long` data words, and the four
operands that reached an object by a fixed displacement from a base register
holding an image address), classifies each, and says what was done.

Classes:

1. **hardware register or PROM cell** - legitimately absolute; kept as a
   named `.set`/`.equ` (or literal) with a comment.  arch/m68k/sau2/hw.h is
   C-only (casts), and the `.s` files are not preprocessed, so no shared
   include was added; the display addresses cite hw.h, the MMU/PEB/timer
   registers are not in hw.h yet (they move there as their modules convert).
2. **data cell that is now a C object or a MODULE_DATA block field** - now
   the symbol, or a `.set NAME, BLOCK + off` alias next to the file's other
   aliases.
3. **code address of a routine in our tree** - now the symbol.
4. **code or data address not yet translated** - literal kept, with a
   `TODO(<bead>)` comment; one P3 bead per owning subsystem.
5. **not an address** (status codes, masks, magic numbers, the 0xCC0000
   user/kernel VA limit, assembly-time `.if` size assertions) - unchanged.

Every conversion keeps the instruction encoding (abs.l stays abs.l,
`#imm.l` stays `#imm.l`, `.long` stays `.long`); only the four
base-register cases grow from `(d16,An)` to `(xxx).l` (2 bytes each), because
a displacement off an image-address base cannot name a relinked object.

## The gate

`tools/asm_compare.py` (wired into `make check` as `check-asm`) compares
every code section of every sau2 object run by run with the image bytes and
resolves every relocation and widened operand in the image's address space
against the operand the image instruction has (see the script header for the
rules).  The image bytes are in the checked-in `tools/asm_image_ref.txt` (112
runs, one line each: address, length, bytes), extracted once from Ghidra with
`asm_compare.py --extract`; `make check` needs neither Ghidra nor the image.
Regenerate it only when a run is added or grows.  The gate also prints a
note for every pair of consecutive runs that are not contiguous in the
image (the bytes between them are compared with nothing): 14 today, all
explained by routines the image keeps elsewhere, data cells between
routines, the C neighbours of a run, or trampolines whose bodies are in the
SMD code segment; the count is in the summary line, so a new one shows.
